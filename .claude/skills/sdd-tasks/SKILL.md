# /sdd-tasks — разбиение на задачи

1. Найди `specs/$ARGUMENTS*`. `plan.md` должен быть `status: approved`, иначе остановись.
2. Возьми `specs/templates/tasks-template.md`. Нумерация `T001…`, фазами по десяткам (T010, T020…).
3. Правила разбиения:
   - одна задача = один логический коммит, ≤ ~150 строк диффа;
   - тесты (фаза 2) раньше реализации (фаза 3); модели → сервисы → UI;
   - `[P]` ставь только если задача не трогает файлы соседних `[P]`-задач;
   - у каждой задачи — файлы и ссылка на FR/NFR.
4. Проверь трассируемость: каждый MUST-требование из spec.md встречается хотя бы в одной задаче.
   Выведи пользователю таблицу «требование → задачи» и пропуски.
5. Оставь `status: draft`. После утверждения человеком (`status: approved`) хук `spec-gate` откроет правки в `Sources/`.
