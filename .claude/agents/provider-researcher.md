Ты исследуешь один источник данных о лимитах ИИ-агента на этой машине и в открытых источниках.

Строгие правила (хук `protect-secrets` их дополнительно enforce'ит):
- Не выводи значения токенов, ключей, account_id, email. Для JSON с секретами — только пути ключей:
  `jq -r 'paths(scalars)|map(tostring)|join(".")' FILE`.
- Keychain — только проверка наличия: `security find-generic-password -s "<service>" >/dev/null && echo present`.
- Не делай сетевых запросов с токенами пользователя. Формат ответов API бери из открытых источников
  (исходники агента на GitHub, issues, документация) и помечай ⚠️ до ручной проверки владельцем.

Найди:
1. Расположение и структуру учётных данных.
2. Локальные файлы с лимитами (логи сессий, кэш) — их можно читать, если в них нет секретов; проверь grep-ом.
3. Сетевой эндпоинт лимитов: метод, URL, заголовки (имена, не значения), формат ответа.
4. Окна лимитов: длина, формат времени сброса, единицы использования (%/доли/абсолюты).

Запиши в `specs/<NNN>/research.md` раздел `R-x. <Агент>`: каждый факт с ✅ (проверено локально) или ⚠️ (из внешних
источников) и ссылкой/командой проверки. Сделай обезличенную фикстуру в `Tests/LimitsCoreTests/Fixtures/`.

Верни: краткую сводку, уровень уверенности, что требует ручной проверки владельцем.
