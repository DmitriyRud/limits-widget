# Спецификация: Поддержка Antigravity в виджете лимитов

## Контекст и проблема
Пользователь работает с Google Antigravity наряду с Claude Code и Codex CLI. У Antigravity действуют скользящие лимиты использования по пулам моделей, которые сбрасываются по таймеру. Сейчас виджет показывает только Claude Code и Codex; чтобы видеть остаток лимитов Antigravity на рабочем столе рядом с остальными агентами, нужен отдельный провайдер Antigravity.

## Пользовательские сценарии
- **US-1** Как разработчик, я хочу видеть на рабочем столе процент оставшегося лимита и время до сброса для Antigravity рядом с Claude Code и Codex, чтобы планировать работу с моделями.
  - Given Antigravity авторизован (и запущен, если выбран локальный источник), When смотрю на виджет, Then вижу блок Antigravity с логотипом, индикаторами остатка лимитов (прогресс-бар + %) и обратным отсчётом до сброса.
- **US-2** Если Antigravity не запущен, не авторизован или источник данных недоступен, я хочу видеть понятный статус («Не авторизован», «Нет данных», «Ошибка сети» и т.п.), при этом блоки Claude Code и Codex продолжают работать без сбоев.
- **US-3** Как пользователь, я хочу включать и выключать отображение Antigravity в настройках виджета, так же как Claude Code и Codex.

## Функциональные требования
| ID | Требование | Приоритет |
|----|------------|-----------|
| FR-001 | Определять доступность Antigravity по файлам локального демона (`~/.gemini/antigravity/daemon/hub_*.json`) без изменения локального состояния и учётных данных Antigravity | MUST |
| FR-002 | Получать для Antigravity квоты моделей через локальный `GetUserStatus` и агрегировать их в **один общий индикатор** — модель с минимальным оставшимся процентом лимита (с её временем сброса `resetTime`) | MUST |
| FR-003 | Отображать блок Antigravity в том же формате, что и существующие провайдеры: логотип + название, время актуальности данных, прогресс-бар остатка (высота 10 pt), цветовые пороги (< 30% остатка — предупреждение, ≤ 10% — критично), относительное время до сброса и абсолютное по наведению | MUST |
| FR-004 | Если момент сброса (`resetTime`) уже прошёл, считать лимит модели полностью восстановленным (остаток 100%, использовано 0%) до следующего обновления | MUST |
| FR-005 | Добавить переключатель «Antigravity» в окно настроек виджета; при выключении провайдер не опрашивается | SHOULD |
| FR-006 | Корректно обрабатывать крайние случаи ответа: пустой `quotaInfo: {}` (пропускать), отсутствующий `remainingFraction` при наличии `resetTime` (= 0% остатка), неизвестные поля, смену формата ответа (понятный статус без падения) | MUST |

## Нефункциональные требования
| ID | Требование | Как проверяем |
|----|------------|---------------|
| NFR-001 | Учётные данные и токены Antigravity не логируются, не сохраняются и не покидают процесс (кроме официального хоста провайдера, если используется облачный API) | code review + тест `description` модели учётки |
| NFR-002 | Приложение только читает данные Antigravity и никогда не модифицирует его файлы, базы, Keychain и не делает refresh OAuth-токенов | code review |
| NFR-003 | Сбой провайдера Antigravity не влияет на отображение Claude Code и Codex | unit-тест `LimitsStore` |
| NFR-004 | Сборка `swift build -c release` без предупреждений, Swift 6 strict concurrency | `swift build -c release` |
| NFR-005 | Парсинг ответа и логика провайдера покрыты unit-тестами на обезличенных фикстурах | `scripts/test.sh` |
| NFR-006 | Сохранение бюджета ресурсов: CPU в простое < 1%, RAM < 50 МБ, опрос не чаще 1 раза в 60 с | Activity Monitor |

## Вне рамок (non-goals)
- Обновление (refresh) OAuth-токенов Google или запуск самого Antigravity из виджета.
- Отображение стоимости в долларах или счётчика токенов.
- Изменение настроек или выбор моделей внутри Antigravity.

## Открытые вопросы
- [x] Q-1 Какой источник данных использовать для Antigravity? (`research.md` R-2, R-3)
  - Вариант А: **Локальный language server** (`127.0.0.1`, `GetUserStatus`) — без внешней сети и Google OAuth, но работает только пока запущен Antigravity.
  - Вариант Б: **Облачный API** (`cloudcode-pa.googleapis.com` / `daily-cloudcode-pa.googleapis.com`) — работает при закрытом Antigravity, но требует чтения OAuth-токена (и токен протухает ~через час без refresh).
  - Вариант В: **Гибрид** (приоритет локальному серверу или облаку, второй — фоллбэк).
  → **Решение (2026-11-19):** Гибрид — приоритет локальному language server (соответствует конституции II.4), фоллбэк на облачный API, когда Antigravity закрыт. Затронуто: FR-001, FR-002.
- [x] Q-2 Какие индикаторы показывать в блоке Antigravity? (`research.md` R-4)
  - Вариант А: **Сгруппированные пулы моделей** (дедупликация моделей с одинаковым `remainingFraction` и `resetTime`, например «Gemini Pro», «Gemini Flash», «Claude» — 2–3 строки).
  - Вариант Б: **Все модели с квотой** по отдельности.
  - Вариант В: **Только один общий индикатор** (минимальный остаток среди моделей).
  → ~~**Решение (2026-11-19):** Один общий индикатор — минимальный остаток среди моделей с квотой.~~
  → **Пересмотрено (2026-11-20, владелец):** Показывать **все лимиты** из `RetrieveUserQuotaSummary` (`Gemini · 5 ч`, `Gemini · Неделя`, `Claude & GPT · 5 ч`, `Claude & GPT · Неделя`, `Gemini 4 Argon · Неделя`); фоллбэк на `GetUserStatus` (один общий индикатор) для старых версий хаба. Затронуто: FR-002, FR-003, plan.md.
- [x] Q-3 Нужно подтвердить на машине владельца фактический источник данных (порт/эндпоинт локального `language_server` и путь к OAuth-токену для фоллбэка) и получить обезличенный пример ответа (фикстуру) для `Tests/LimitsCoreTests/Fixtures/antigravity_usage.json` (`research.md` R-1…R-3).
  → **Решение (2026-11-19):** На машине работает Antigravity 2.0 (`agy --hub`), метаданные лежат в `~/.gemini/antigravity/daemon/hub_*.json` (`csrfToken`, `httpPort`, `httpsPort`, `pid`), `GetUserStatus` подтверждён реальным ответом (обезличено в `research.md` R-2). `state.vscdb` отсутствует; облачный фоллбэк выносится в отдельное улучшение, если понадобится после проверки Keychain `"gemini"`. Затронуто: FR-001, FR-002, FR-006, research.md R-1…R-4.
