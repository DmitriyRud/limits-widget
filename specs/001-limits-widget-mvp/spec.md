# Спецификация: MVP виджета лимитов ИИ-агентов

## Контекст и проблема
Пользователь работает одновременно с Claude Code и Codex CLI по подписке. У обоих есть
скользящие лимиты: короткое окно (5 часов — «дневной» лимит) и недельное окно. Узнать
остаток можно только командой внутри агента (`/usage`, `/status`), из-за чего лимит
внезапно заканчивается посреди работы. Нужен постоянно видимый виджет на рабочем столе.

## Пользовательские сценарии
- **US-1** Как разработчик, я хочу видеть на рабочем столе процент использования 5-часового
  и недельного лимита Claude Code, чтобы планировать тяжёлые задачи.
  - Given я авторизован в Claude Code, When открываю рабочий стол, Then вижу два индикатора
    (5 ч и 7 дн) с процентом и временем до сброса.
- **US-2** То же самое для Codex CLI.
- **US-3** Как разработчик, я хочу видеть обратный отсчёт до сброса («через 2 ч 14 мин»),
  чтобы знать, когда можно продолжить.
- **US-4** Если агент не авторизован или данные недоступны, я хочу видеть понятный статус
  («Не авторизован», «Нет данных», «Ошибка сети»), а не пустоту или краш.
- **US-5** Как пользователь, я хочу, чтобы виджет не мешал: висел на уровне рабочего стола,
  был перетаскиваемым, запоминал позицию и запускался при входе в систему.

## Функциональные требования
| ID | Требование | Приоритет |
|----|------------|-----------|
| FR-001 | Определять, авторизован ли пользователь в Claude Code по его локальным учётным данным (где они лежат — research.md R-1) | MUST |
| FR-002 | Получать для Claude Code: % использования и время сброса 5-часового и 7-дневного окна (+ отдельное недельное окно Opus/Sonnet, если оно есть) | MUST |
| FR-003 | Определять, авторизован ли пользователь в Codex по его локальным учётным данным (`~/.codex/auth.json`, только чтение; research.md R-2) | MUST |
| FR-004 | Получать для Codex: % использования и время сброса 5-часового и недельного окна **с сервера Codex** (`chatgpt.com`, research.md R-2), чтобы учитывалось использование и вне этого Mac. Если сетевой запрос не удался (нет сети, токен истёк, формат изменился) — использовать локальные журналы сессий Codex (данные на момент последнего обращения к Codex) | MUST |
| FR-005 | Показывать для каждого окна: название, прогресс-бар, **% оставшегося лимита** (100 − % использования), относительное время до сброса, абсолютное время сброса (по наведению). Прогресс-бар показывает остаток (высота 10 pt). Перед названием агента — его логотип | MUST |
| FR-006 | Обратный отсчёт обновляется раз в минуту без сетевых запросов; данные — раз в N секунд (по умолчанию 300, минимум 60) | MUST |
| FR-007 | Цвет индикатора по использованию: < 70% использовано (остаток > 30%) — норма, 70–90% (остаток 10–30%) — предупреждение, ≥ 90% (остаток ≤ 10%) — критично | SHOULD |
| FR-008 | Для каждого агента показывать время, на которое актуальны данные (для Codex из локальных журналов — время последнего обращения к Codex); если обновление не удалось — пометку «данные устарели». Если данные не за сегодня — показывать дату, а не только время | MUST |
| FR-009 | Окно-виджет на уровне рабочего стола, без системной рамки окна, перетаскиваемое, позиция сохраняется. Оформление — как у системных виджетов macOS: скруглённая тёмная подложка с тонкой светлой обводкой | MUST |
| FR-010 | Иконка в меню-баре с действиями: «Обновить», «Настройки», «Запускать при входе», «Выход» | SHOULD |
| FR-011 | Автозапуск при входе в систему (включается пользователем) | SHOULD |
| FR-012 | Если окно уже сброшено (resets_at в прошлом), показывать 0% до следующего обновления | MUST |
| FR-013 | Провайдеры включаются/выключаются в настройках | COULD |

## Нефункциональные требования
| ID | Требование | Как проверяем |
|----|------------|---------------|
| NFR-001 | Токены не логируются и не покидают процесс, кроме запроса к официальному хосту провайдера | code review + grep-хук + тест на `description` модели учётки |
| NFR-002 | CPU в простое < 1%, RAM < 50 МБ | Activity Monitor, 10 мин |
| NFR-003 | Сбой одного провайдера не влияет на другие | unit-тест агрегатора |
| NFR-004 | Сборка `swift build -c release` без предупреждений, Swift 6 strict concurrency | CI/хук |
| NFR-005 | Покрытие парсеров и форматтеров unit-тестами на фикстурах | `swift test` |
| NFR-006 | Приложение не изменяет файлы и Keychain-элементы агентов | code review |

## Вне рамок (non-goals)
- Обновление (refresh) OAuth-токенов — если токен истёк, показываем «Откройте Claude Code / Codex для повторной авторизации».
- Подсчёт стоимости в токенах/долларах (как ccusage).
- API-ключи с оплатой по факту (pay-as-you-go) — только подписочные лимиты.
- WidgetKit-виджет в Notification Center (см. ADR-001, возможно в 002).
- Другие агенты (Gemini CLI, Cursor) — добавляются через скилл `add-provider` отдельными спеками.

## Изменения после утверждения
- 2026-11-09, решение владельца (по итогам первого запуска): виджет показывает **оставшийся** процент лимита вместо
  использованного (FR-005, FR-007 переформулированы, пороги не изменились); время актуальности данных показывается с датой,
  если оно не сегодняшнее (FR-008) — устаревшие данные Codex выглядели как свежие.
- 2026-11-09, решение владельца: пересмотр Q-2 — лимиты Codex запрашиваются по сети у `chatgpt.com`, локальные журналы —
  фоллбэк (FR-003, FR-004, FR-008, non-goals). Конституция II.3 разрешает `chatgpt.com` для OpenAI.
- 2026-11-09, решение владельца (по скриншоту системного виджета): рамка как у виджетов macOS, логотип агента перед
  названием, шкалы остатка в 2 раза выше (FR-005, FR-009). Логотипы — векторные SVG из simple-icons 15.0.0 (CC0),
  встроены строкой в код провайдера (без ресурсов); UI получает их через протокол, не зная конкретных агентов (IV.2).
