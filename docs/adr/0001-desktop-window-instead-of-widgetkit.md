# ADR-0001: Окно на уровне рабочего стола вместо WidgetKit

- Статус: предложено (утверждается вместе с `specs/001-limits-widget-mvp/plan.md`)
- Дата: 2026-11-09

## Контекст
Начиная с macOS 14 WidgetKit-виджеты можно размещать на рабочем столе. Но:
- WidgetKit-расширение обязано быть в песочнице → нет доступа к `~/.codex` и чужим Keychain-элементам;
  нужен хост-процесс + App Group + подписанный Team ID.
- Требуется Xcode-проект и provisioning, что ломает принцип III.2 (сборка через `swift build`).
- Таймлайн обновляется по бюджету системы, обратный отсчёт поминутно не гарантирован.

## Решение
MVP — SwiftPM-приложение (`LSUIElement`, без иконки в Dock) с `NSPanel` без рамки на уровне
`CGWindowLevelForKey(.desktopIconWindow) + 1` (над значками, под обычными окнами; см. «Уточнение»), `collectionBehavior = [.canJoinAllSpaces, .stationary]`,
контент — SwiftUI. Плюс `MenuBarExtra` для управления.

## Последствия
+ Полный доступ к файлам/Keychain без песочницы, сборка одной командой, точный таймер.
− Не «настоящий» системный виджет: нет редактирования через «Изменить виджеты».
→ WidgetKit-вариант можно добавить позже (спека 002), переиспользуя `LimitsCore` целиком.

## Уточнение (2026-11-09, решение владельца)
Уровень панели — `desktopIconWindow + 1`, а не ровно `desktopIconWindow`: на уровне окна значков Finder порядок
относительно значков не гарантирован и перетаскивание мышью (FR-009) может не работать. Проверено при первом запуске:
виджет перетаскивается и сохраняет позицию. Отклонение D-1 в `specs/001-limits-widget-mvp/plan.md` принято.
